Your data, explained

Privacy Policy

Last updated: 19 October 2026

In short

FAIR keeps expense records in SQLite on the device and syncs structured records with Supabase when connected. If you scan a receipt, the selected image is sent to FAIR’s backend and forwarded to its configured OCR service so FAIR can return parsed items.

What FAIR stores

FAIR uses two databases for the app’s expense and group information:

  • Local database: SQLite stores profile, group, member, receipt, item, assignment, debt, and settlement records on the device.
  • Cloud database: Supabase stores account and structured expense records that the app synchronizes. Supabase also provides account authentication.

The app stores the selected receipt’s extracted details in the expense record. The receipt photo itself is not a stored image attachment in the receipt record.

Receipt scanning

When you choose receipt scanning, the app uploads the image over the network to FAIR’s authenticated FastAPI backend. The backend validates the image and sends its contents to the configured remote OCR service. The backend parses the OCR text and returns candidate item details to the app. Scanning will not work without internet access and available processing services.

The project code does not establish how long the external OCR provider retains request data. Review that provider’s current terms and privacy information before scanning sensitive receipts.

Sync and account data

On initial account loading, FAIR fetches your profile and cloud groups, members, receipts, items, assignments, debts, and settlements into SQLite. Local records are flagged as needing sync when changed. Sync operations upload local changes to Supabase, and the Profile screen offers a manual sync action. Sync requires an internet connection.

FAIR’s Supabase configuration and policies determine cloud access and retention. The source repository alone cannot confirm the deployed project’s backups, row access policies, or retention settings.

Sharing a receipt summary

Copy Split places a plain text summary on your device clipboard. Share Split opens the operating system share sheet with that text. The summary can include the group, date, receipt title, items, totals, payer, and debts. It is sent to an app or person only if you choose a destination in the share sheet.

Account and data deletion

FAIR includes account and data deletion actions in the app. Cloud deletion behavior depends in part on the deployed Supabase schema and its relationships. Deleting local app data removes the local copy; it does not by itself erase cloud records. Use the in-app account deletion flow to request cloud-side deletion.

Services and changes

FAIR uses Supabase for authentication and structured cloud data, a FAIR FastAPI backend for receipt processing, and a remote OCR provider configured by the backend. The service configuration may change. This page should be updated when the data flow, providers, or retention practices change.
